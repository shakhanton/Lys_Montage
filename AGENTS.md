# Repository Guidelines

## Project Structure & Module Organization

This repository currently contains only `prompt.md`, the Ukrainian-language brief for a plumbing services website for Andriy. Read it before making changes. No application source, tests, assets, or dependency manifests exist yet.

When implementation begins, separate application code, reusable components, and local image assets into clearly named directories. Document the chosen structure and entry points here once established.

## Build, Test, and Development Commands

No build, development, lint, or test commands are currently configured. Do not assume that commands such as `npm test` or `npm run build` are available.

When selecting a stack, provide reproducible installation, local development, and production build commands in a README. Define relevant scripts in the project's dependency manifest and update this guide with their actual usage.

## Coding Style & Naming Conventions

Follow the conventions of the selected language and framework; establish consistent indentation and configure an appropriate formatter and linter. Use descriptive component names and filenames, and keep content separate from presentation where practical.

Write visitor-facing copy in natural Ukrainian. Use semantic markup, accessible controls, meaningful image alternative text, and responsive layouts.

## Content & Asset Integrity

Treat `prompt.md` as the source of project requirements. Record source links for each business claim and selected photograph. Use only verified photographs of Andriy or his work; exclude stock images, generated photographs, private family images, and unrelated reposts.

Do not invent services, prices, experience, guarantees, geography, or brand partnerships. Preserve the supplied testimonial's meaning and attribution. Use the working Instagram profile as the contact destination when other business contacts are unavailable.

## Testing Guidelines

No testing framework or coverage threshold is established. Add tests for meaningful application behavior as implementation develops.

Before delivery, check mobile and desktop layouts, navigation, contact links, image loading, contrast, and metadata. Verify business claims against recorded sources. Add a request form only with working message delivery.

## Commit & Pull Request Guidelines

No Git history is available to establish existing conventions. Use concise, imperative commit subjects, such as `Add responsive services gallery`.

Pull requests should describe changes, validation performed, and remaining limitations. Include screenshots for visual changes and source references for new business claims or photographs.
